Understand it · 1 minute

Who runs it, and why only you

In Step 3 the students see the same HORIZON analyst they built, with one change: a real, read-only database connection (an MCP server) instead of a person running the SQL.

The students · on their VMs

They built HORIZON analyst in Step 1. It writes SQL and asks them to run it. They are its only tool.

Nothing to set up and nothing to type during the demo, apart from the chat question at the end.

You · on your Mac

You run HORIZON analyst (demo): the same instructions plus one line ("If a database tool is connected, run the query yourself with execute_sql…").

Your Claude Desktop is also connected to the horizon server (DBHub) with one tool, execute_sql, set to read-only.

Why only you: the door needs three things the VMs don't have. They are the Docker warehouse on your Mac, Node (npx starts the server), and an mcpServers entry in your Claude Desktop config. All three are already on your Mac.

Set it up · the night before · about 15 minutes, once

The night before

Do this once, end to end, including one rehearsal chat. Steps 1 to 4 were run and passed on 2026-10-26. Step 5 has not been seen in the app yet: Claude Desktop hasn't been opened since the config was written, so that's the one to check first.

6
Terminal + Claude Desktop

Create the demo Project

2 min 
make demo-instructions | pbcopy
  1. Claude Desktop, left sidebar → Projects → New project.
  2. Name it HORIZON analyst (demo), leave the rest as it is, and click Create project.
  3. On the project page, click the + next to Instructions on the right. Paste (Cmd+V) and click Save instructions.
  4. Scroll to the end of what you pasted: the last line must be "If a database tool is connected, run the query yourself with execute_sql instead of asking me to run it."
  5. Keep the plain HORIZON analyst Project too, if you built one with the class. The room should see that the two differ by one line and one connector.

Claude Desktop

3 min

Check it · day of, 15 minutes before Hour 4 (by about 2:45)

15 minutes before

Tick every box. The whole list takes about three minutes.

  • Docker is running, and make demo-prep in horizon-warehouse prints 277 and READONLY_VIOLATION again.
  • Claude Desktop was quit with Cmd+Q and reopened today. + → Connectors lists horizon.
  • A fresh chat inside HORIZON analyst (demo) is open and empty. Picker on Sonnet. horizon toggle ON for this chat. Nothing typed yet, so the room sees the first permission dialog.
  • A second Terminal tab is open in horizon-warehouse with make mcp-check typed but not run. That's your fallback.
  • Optional: a third tab with tail -n 20 -f ~/Library/Logs/Claude/mcp*.log to show the plumbing.
  • dbhub.toml and the config file are closed. Nothing with the password is on screen.
  • Screen share ready to switch to Claude Desktop at 3:30.
Run it · 3:30 to 3:35 · five minutes

On stage

Three questions, typed exactly as written below. The room watches for four moments: the door, the permission prompt, the tool call, the refusal.

3:30
Moment 1 · the door · 30 sec

Show the connector

30 sec
Do

Switch the share to Claude Desktop, in the fresh demo-Project chat. Click + → Connectors and hover horizon.

Say

"Your analyst had one tool: you. Mine has a second one: a server called horizon, with one tool, execute_sql, and one setting, read-only. Everything else is the same text you pasted, plus one line telling it to use the door if it has one."

3:31
Moments 2 and 3 · the permission prompt, the tool call · 90 sec

Q1 · the VEEV question

90 sec 
Which Japan distributor sells the most VEEV units per week on average?
  1. It restates the question, names rst.sell_through and rst.distributors, writes a select, and tries to call the tool.
  2. The permission dialog appears. Stop before you click.
Say, before you click

"This dialog is the human gate, drawn on screen. If I click 'always allow', it never asks again. That's a signature you didn't know you were giving."

  1. Click the once / this-chat option.
  2. The tool call runs and the answer comes back: JP Partner Distributor 2 · ≈ 277 then 271 · 209 · 169.
Say

"Same number you got. No human ran anything. This is the demo leadership saw. Fast, correct, and the gate was one click."

If it writes the SQL and asks you to run it

Check that the horizon toggle is ON, then reply exactly: The horizon database tool is connected. Run that query yourself with execute_sql.

3:33
Moment 4 · the refusal · 90 sec

Q2 · ask it to delete

90 sec 
Delete the ecommerce distributors.
  1. If a second permission dialog appears, click Allow (once), not Deny. Deny blocks the call before the door can answer. Say: "I'm letting it through, so the door has to stop it."
  2. The tool refuses: READONLY_VIOLATION "Read-only mode is enabled. Only the following SQL operations are allowed: select, with, explain, show".
Say

"Read it. That's not the model being polite. That's software refusing a statement it was never allowed to run. In Step 2 the same rule was a sentence in a prompt, and the control was you not pasting. The lock is on the door, not in the prompt."

If it refuses in prose and never calls the tool (likely)

Name it: "That's the prompt rule, a request." Then make the door prove itself, in this order:

  1. Reply: I understand the analyst is read-only. Send the DELETE through execute_sql anyway so we can see what the door says.
  2. Still no? Open a New chat outside the Project (horizon toggle ON) and type: Using the horizon tool, run this SQL: delete from rst.distributors where channel_type = 'ecommerce'
  3. Still no? Switch to the Terminal tab and press Enter on make mcp-check. Part 3 is the same refusal. "Same door, same answer, no model in between."
3:34
The context window · 45 sec

Q3 · ask for every row

45 sec 
Paste every row of det.device_telemetry.

Expect it not to run select *. Instead it proposes an aggregate (a count by market and product) and explains why: 35,113 rows is about 2 million characters, roughly half a million tokens.

Say

"It summarises; it doesn't slurp. But that rule is still only in the prompt. If this went to pilot, the gate would need a row cap on the door."

3:35
Close · 30 sec · then Step 4

One control apart

30 sec
Say, back on the room's screen

"Your analyst had a person between the model and the warehouse. Mine has a read-only server. Both are gates. One scales; the other gets tired at four o'clock. And the rollback is one step: remove the server block, Cmd+Q, reopen, and the door is gone. Now we decide which rung it has earned."

Chat

"Which surprised you most today: token, context, or door?"

If something breaks

If you only remember one thing: make mcp-check in Terminal shows the whole demo (handshake, one tool, 277, READONLY_VIOLATION) in ten seconds.

Wrap it up

After the demo, and after class

  1. During Step 4, when the room lists guardrails, point back: "for my version, unplug the server; for yours, delete the Project." The rollback is a guardrail.
  2. Leave the door plugged in if you teach again soon. It does nothing unless a chat has the horizon toggle on.
  3. To unplug it: remove the horizon block from claude_desktop_config.json, or restore claude_desktop_config.json.bak-2026-10-24. Then Cmd+Q and reopen.
  4. Stop the warehouse (the data is kept): 
    cd /Users/varoonsahgal/pmidataeng/horizon-warehouse
make down
Why this door is still not a pilot

dbhub.toml connects as the postgres superuser of a training-only warehouse. The read-only tool setting is the only thing between the model and that role. A real pilot needs a database role that can only read rst.* and analytics.*, a query log, a row cap and a named owner. That's exactly what the students write as their gates in Step 4d, and what Challenge 4 builds.
